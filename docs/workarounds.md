# Временные обходы

`WORKAROUND <ID>` в коде содержит причину, известную версию, ссылку на upstream (если она есть) и условие удаления. При новом обходе добавьте такой комментарий рядом с изменением и строку сюда. Если проблема привязана к версии, оберните результат в `lib.warnIf (lib.getVersion пакет != "проверенная-версия") "WORKAROUND <ID>: версия изменилась; проверьте обход" значение`. Для flake input сравнивайте его `rev`. Предупреждение означает повод проверить штатный пакет, а не доказательство, что обход можно удалить.

После ручного обновления `flake.lock` проверьте предупреждения при evaluation, попробуйте штатный пакет без обхода и проверьте его работу. Если обход больше не нужен, удалите его комментарий и строку реестра вместе с кодом.

GitHub Actions на `push`, `pull_request` и вручную вычисляет `system.build.toplevel` для обоих хостов, затем выполняет `nix build --dry-run --no-link`. Предупреждения `lib.warnIf` остаются в логе. Проверка выявляет ошибки evaluation и недоступные зависимости на этапе планирования, но не компилирует пакеты, не запускает графические приложения и не проверяет работу на реальном железе. Успешный CI поэтому не гарантирует сборку или работу Wayland, Qt и VPN.

## STEAM-UI-STARTUP

**Статус:** временный локальный патч, применён 2026-11-12 на `desktop-amd` для пользователя `alexmcgil`. Сборка клиента Valve — `1794424036` (2026-11-09). Подтверждённый upstream issue не найден; точная причина отсутствия ответа внутри нативного клиента не установлена.

### Что произошло

Процессы Steam и `steamwebhelper` запускались, но окно входа не появлялось. В `~/.local/share/Steam/logs/webhelper_js.txt` инициализация `ControllerStore` завершалась только при закрытии Steam, когда отменялись ожидающие запросы. Через локальный отладчик интерфейса подтверждено: зависал `SteamInputManager.GetControllerAccessibilityStrings#1`, остальные запросы завершались. Это запрос подписей кнопок для интерфейса; зависание воспроизводилось и без подключённого геймпада.

Переключение на 32-битный клиент, английский язык, новый кэш интерфейса и полная проверка контрольных сумм файлов не помогли. Предупреждение `MESA-LOADER ... dri_gbm.so` встречалось и в прежних успешных запусках и не было подтверждено как причина этой неисправности.

### Что изменено

В `~/.local/share/Steam/steamui/sp.js` заменён ровно один фрагмент. Ожидание ответа больше не блокирует инициализацию; запрос продолжает выполняться, и при получении ответа подписи добавляются в ту же таблицу.

До:

```javascript
(await m.f_.GetControllerAccessibilityStrings({})).Body().toObject().strings.forEach(je=>{this.m_mapControllerGlyphStrings.set(JSON.stringify(je.key),je.localized_string)})
```

После:

```javascript
m.f_.GetControllerAccessibilityStrings({}).then(r=>r.Body().toObject().strings.forEach(j=>{this.m_mapControllerGlyphStrings.set(JSON.stringify(j.key),j.localized_string)}))
```

Оба фрагмента занимают 172 байта; размер файла сохранён — 16 224 005 байт. Поэтому обычная проверка размеров при запуске не заменяет патч. Проверка контрольных сумм (`steam -verifyfiles`) или обновление клиента может восстановить штатный файл. Проверка файлов не отключалась.

Оригинал сохранён вне репозитория:

```text
~/.local/state/steam-startup-fix/sp.js.1794424036.original
```

SHA-256 на момент исправления:

| Файл | SHA-256 |
| --- | --- |
| Оригинал / резервная копия | `4b818cd371388e06c66fe8c0bb592b7dfd4a6fb55eb56844d1b360b64aec3046` |
| Файл с патчем | `0e814a6cab4251abb7143c038ed12f6b5b64a29ca7283aba4daf18846800bbef` |

Исходный кэш интерфейса восстановлен, русский язык и штатный SteamRT3 возвращены. Диагностический режим выключен; порт отладки `127.0.0.1:18277` закрыт. Для запуска достаточно `steam`.

Это изменение самообновляемого клиента Valve в домашнем каталоге, а не пакета `pkgs.steam` или flake input. `nrs`, `nrsu`, откат поколения NixOS и CI не применяют и не откатывают этот патч. `lib.warnIf` по версии `pkgs.steam` не отслеживает сборку клиента Valve, поэтому здесь его нет. При изменении сборки клиента нужно отдельно проверить штатный запуск; автоматически переносить замену в другую версию нельзя.

### Что проверено и какие ограничения

- Самопроверка замены: инициализация продолжается при незавершённом запросе, а подписи заполняются, если ответ приходит позже.
- Полный файл прошёл `node --check`.
- При обычном запуске без отладчика инициализация интерфейса заняла около 0,3 секунды, окно входа появилось примерно через 2 секунды.
- Пользователь подтвердил вход и открытие библиотеки после обхода, затем подтвердил работу после применения файлового патча.

Запуск игр и функции доступности отдельно не проверялись. Пока запрос не отвечает, таблица подписей остаётся пустой; патч устраняет блокировку запуска, но не исправляет отсутствие ответа в клиенте.

### Как откатить

**Рекомендуемый способ, в том числе после обновления клиента:** полностью выйти из Steam через меню «Выход» и дождаться завершения его процессов (`pgrep -x steam` не должен показывать PID). Затем в терминале графической сессии выполнить:

```fish
steam -verifyfiles
```

Steam проверит контрольные суммы и восстановит штатные файлы для установленной/доступной сборки. Это может потребовать скачивания файлов клиента. В `logs/bootstrap_log.txt` должна появиться строка `Verifying all file checksums`. После восстановления проверить появление окна и вход, затем ещё один обычный запуск через `steam`.

**Ручной откат из резервной копии допустим только для того же файла сборки `1794424036`.** После полного выхода из Steam проверить обе контрольные суммы:

```fish
sha256sum ~/.local/share/Steam/steamui/sp.js ~/.local/state/steam-startup-fix/sp.js.1794424036.original
```

Только если первая сумма совпадает со строкой «Файл с патчем», а вторая — со строкой «Оригинал» выше, восстановить файл:

```fish
cp -- ~/.local/state/steam-startup-fix/sp.js.1794424036.original ~/.local/share/Steam/steamui/sp.js
steam
```

Если суммы отличаются, использовать проверку Steam, а не старую резервную копию: нельзя подменять файл нового клиента файлом от `1794424036`. На неисправной сборке откат может вернуть зависание.

Удалять запись `STEAM-UI-STARTUP` из таблицы и комментарий в `modules/apps/steam.nix` вместе только после успешной проверки штатного клиента без патча на `desktop-amd`. Успешная пересборка NixOS или смена версии клиента сами по себе не являются основанием для удаления.
