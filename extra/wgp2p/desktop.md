# wgp2p без VPS: desktop-amd ↔ laptop-intel

Десктоп одновременно является сервером WireGuard и участником сети. Его адрес
остаётся `10.66.66.2`, ноутбука — `10.66.66.3`; старый `10.66.66.1` не используется.
Трафик идёт напрямую между машинами. Форвардинг и MASQUERADE для этого не нужны.
В туннель направляется только адрес второй машины, без смены DNS/default route.

Внешние UDP-пакеты wgp2p на десктопе получают fwmark `51830` и через правило
с приоритетом `100` используют таблицу `51830`: шлюз `192.168.0.1`, интерфейс
`eno1`. Это обходит корпоративный маршрут openconnect к публичному адресу
ноутбука, из-за которого ответы на handshake уходили в `tun0`. Остальной
трафик сохраняет прежнюю маршрутизацию. При смене домашнего шлюза/интерфейса
обновить `wgp2p-uplink` в `modules/wireguard-p2p.nix`.

## Роутер и DNS

- Закрепить за desktop-amd LAN-адрес `192.168.0.107`.
- Пробросить **UDP 51830 → 192.168.0.107:51830**.
- A-запись `vpn.fack.su` направить на внешний IPv4 роутера, без HTTP/CDN-прокси.
- Не публиковать AAAA, если входящий WireGuard по IPv6 не настроен.
- При CGNAT нужен доступный извне адрес от провайдера: одного проброса на домашнем роутере недостаточно.

SSH и Sunshine не требуют проброса своих портов в интернет.

## desktop-amd (NixOS)

`modules/wireguard-p2p.nix` использует существующий приватный ключ
`/etc/nixos/secrets/wgp2p.key`, слушает UDP 51830 и принимает только публичный
ключ ноутбука с адресом `10.66.66.3/32`. Интерфейс запускается при загрузке.
Старый `wgp2p.psk` больше не используется, но автоматически не удаляется.
В новом соединении нет PSK: приватные ключи остаются на своих машинах,
а для настройки достаточно двух публичных ключей.

```bash
sudo nixos-rebuild switch --flake '.#desktop-amd'
sudo wg show wgp2p
```

Проверка обхода корпоративного VPN на десктопе (адрес взять из `endpoint`
ноутбука в `wg show`; во время настройки это был `171.25.167.54`):

```bash
ip route get 171.25.167.54
ip route get 171.25.167.54 mark 51830
```

Вторая команда должна показать `via 192.168.0.1 dev eno1 table 51830`,
даже если первая выбирает `tun0`. Это проверяет маршрут внешнего WireGuard,
а не расшифрованных пакетов `10.66.66.2/32` и `10.66.66.3/32`.

Sunshine запускается вместе с графической сессией, SSH — вместе с системой.
Существующие SSH authorized_keys и настройки/сопряжения Sunshine сохраняются.

## laptop-intel (CachyOS + Home Manager)

Home Manager через `nrs` размещает **публичный** конфиг в
`~/.config/wgp2p/wgp2p.conf`. Системный сервис требует однократной установки
root-owned копии в `/etc/wireguard/wgp2p.conf`; нельзя давать root-сервису
симлинк на изменяемый пользователем конфиг с командами PostUp.
После следующих изменений публичного конфига нужно повторить его установку
и перезапустить сервис. Само подключение после загрузки автоматическое.

Миграцию выполнять в локальном терминале ноутбука. Ниже предполагается, что
старый интерфейс `wgp2p` ещё поднят, как при получении его публичного ключа.
Перед остановкой сохраняем приватный ключ локально, проверяя соответствие
известному публичному ключу; на экран и в репозиторий секрет не попадает.

```bash
sudo bash -c '
set -euo pipefail
umask 077
key=$(wg show wgp2p private-key)
test "$(printf "%s\n" "$key" | wg pubkey)" = "fbpc4FO0RhWJCKFjo5J1TiJzi+IjmhGenpajDd0fCR8="
install -d -m 700 /etc/wireguard
printf "%s\n" "$key" | install -m 600 /dev/stdin /etc/wireguard/wgp2p.key
cp -a --no-clobber /etc/wireguard/wgp2p.conf /etc/wireguard/wgp2p.conf.before-desktop
'
```

Если команда завершилась ошибкой, не продолжать до её исправления.
Секретный файл и резервная копия остаются только в `/etc/wireguard` ноутбука.

После обновления репозитория и `nrs`:

```bash
sudo systemctl stop wg-quick@wgp2p
sudo install -m 600 ~/.config/wgp2p/wgp2p.conf /etc/wireguard/wgp2p.conf
sudo systemctl enable --now wg-quick@wgp2p
```

Без Home Manager можно установить `extra/wgp2p/laptop-intel.conf` той же
командой `install`. Конфиг не содержит PrivateKey: PostUp читает его из
root-only `/etc/wireguard/wgp2p.key` при каждом старте. `SaveConfig` не включать,
иначе wg-quick запишет приватный ключ обратно в публичную часть конфига.

Если интерфейсом раньше управлял NetworkManager, сначала отключить автозапуск
его старого профиля и остановить его: у интерфейса должен быть один владелец.
Команды выше рассчитаны на прежний `wg-quick@wgp2p`.

## Проверка и работа

На ноутбуке:

```bash
sudo wg show wgp2p
ip route get 10.66.66.2
ping -c 3 10.66.66.2
ssh alexmcgil@10.66.66.2
```

Ожидаются свежий handshake, маршрут через `wgp2p` и доступ по прежнему SSH-ключу.
В Moonlight добавить хост вручную по `10.66.66.2`: автоматическое обнаружение
через маршрутизируемый WireGuard не требуется. Для нового сопряжения открыть
`https://10.66.66.2:47990` и ввести PIN Moonlight в Sunshine.
Нужна активная графическая сессия desktop-amd и доступный захват экрана.

Если handshake отсутствует, проверить DNS, проброс UDP и внешний IP.
При смене IP в DNS перезапустить `wg-quick@wgp2p` на ноутбуке: wg-quick
разрешает endpoint при старте, периодическое обновление DNS здесь не настроено.
Корпоративный VPN с принудительной маршрутизацией/kill switch может мешать
внешнему UDP; проверить его отдельно, если туннель работает только без него.
MTU 1360 сохранён из прежней схемы для работы рядом с openconnect.

## Откат ноутбука

```bash
sudo systemctl stop wg-quick@wgp2p
sudo cp -a /etc/wireguard/wgp2p.conf.before-desktop /etc/wireguard/wgp2p.conf
sudo systemctl start wg-quick@wgp2p
```

Это возвращает прежний конфиг, но недоступность старого VPS не исправляет.
